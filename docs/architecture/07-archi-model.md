# Редактируемая архитектурная модель для Archi

Модель: [rtk-crm.archimate.xml](rtk-crm.archimate.xml). Дата: 19.09.2026. Содержит **39 элементов, 45 типизированных связей и 2 представления** с координатами, цветами слоёв и описаниями ответственности. Это целевая архитектура, согласованная с пакетом `01–06`, а не перечень уже реализованных компонентов.

## Содержание представлений

| Представление | Что позволяет проверить |
|---|---|
| `01 · Функции, роли и границы модулей` | Менеджер/руководитель/администратор → бизнес-функции → прикладные сервисы → модули с владельцами A/B. Показывает работу с учреждениями, учебное сопровождение, контроль/отчёты, управление и обмен данными |
| `02 · Компоненты исполнения и внешние границы` | React, HTTPS edge, FastAPI, отдельные dispatcher/worker-процессы, PostgreSQL CRM и Keycloak, Redis, S3, scanner, LMS и Laravel, метрики и восстановление. Подписанные потоки поясняют протокол/назначение обмена |

У каждого элемента и связи есть `Documentation`: границы ответственности, важные ограничения, режим отказа либо назначение потока. Это полезнее одной подписи на схеме: например, у Redis указано восстановление из PostgreSQL, у scanner — сохранение quarantine при сбое, у отчётных workers — необходимость подтвердить 10 параллельных расчётов нагрузочным испытанием.

`A/B` обозначают владельцев исходного кода, а не права бизнес-пользователей. `learning` принадлежит A и записывает первичные учебные факты; `analytics/reports` принадлежат B и читают согласованные проекции. HTTP API и workers используют один модульный backend; отдельная фигура не означает отдельный репозиторий или микросервис. Общие зависимости AccessPolicy, UnitOfWork и jobs подробно определены в [контрактах](05-contracts-and-parallel-development.md), а не размножены всеми возможными стрелками в функциональном представлении.

Цвета соответствуют слоям: жёлтый — бизнес, голубой — приложение, зелёный — технологические компоненты. Они не обозначают зоны доверия. Схема компонентов не заменяет план сетевых ACL и конфигурацию production. Две PostgreSQL-фигуры обозначают разные базы/учётные записи CRM и Keycloak; они могут находиться в одном PostgreSQL cluster.

## Открытие и редактирование в Archi

1. В Archi выбрать **File → Import → Open Exchange XML Model…**.
2. Выбрать `rtk-crm.archimate.xml`. Формат импорта создаёт новую модель в дереве Models.
3. Открыть оба представления в разделе Views; документация доступна в свойствах выбранного элемента/связи.
4. Сохранить рабочую модель как `rtk-crm.archimate` через Save As. XML Exchange — переносимый формат обмена; `.archimate` — рабочий формат Archi.
5. После правок экспортировать **File → Export → Model To Open Exchange File…**, включив проверку XSD. При изменении модели обновлять соответствующие разделы `01–06` в том же PR.

Пункты меню и назначение Exchange подтверждены [официальным руководством Archi, раздел The Open Group Exchange File Format](https://www.archimatetool.com/downloads/archi/Archi%20User%20Guide.pdf). Для автоматизации Archi также предоставляет `--xmlexchange.import` и `--saveModel` в своём [официальном CLI](https://github.com/archimatetool/archi/wiki/Archi-Command-Line-Interface); конкретный путь executable зависит от установки.

## Формат и фактически выполненная проверка

Использован **The Open Group ArchiMate Exchange 3.1**. Пространство имён в XML остаётся `http://www.opengroup.org/xsd/archimate/3.0/`: это namespace официальных схем 3.1, не ошибка версии. Схема модели, представлений и диаграмм загружена с сайта The Open Group; зависимость XML namespace — с W3C. Общие сведения о стандарте — [The Open Group](https://www.opengroup.org/open-group-archimate-model-exchange-file-format).

19.09.2026 выполнены проверки Python `lxml 6.1.1`:

- XML успешно проверен методом `XMLSchema.assertValid` по официальному `archimate3_Diagram.xsd` и его включениям Model/View.
- Все идентификаторы уникальны; все `elementRef`, `relationshipRef`, `source`, `target`, `identifierRef` указывают на существующие объекты.
- Каждый графический connector ссылается на relationship, чьи исходный/конечный элементы совпадают с элементами соответствующих узлов диаграммы.
- В модели ровно 2 диаграммы, 39 графических узлов и 45 графических связей.

**Импорт и визуальная проверка в GUI Archi не выполнялись.** XSD подтверждает структуру/типы XML, но не заменяет проверку читаемости расположения в конкретной версии Archi или экспертную проверку семантики всех отношений. Перед финальной сдачей ТЗ необходимо импортировать модель, проверить оба вида и сохранить `.archimate`; это явно остаётся частью приёмки архитектурного артефакта.
