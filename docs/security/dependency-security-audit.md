## 4. Доказательство соблюдения философии Ponytail (The Ladder: Stdlib-First)

В соответствии с правилами разработки (`AGENTS.md`, раздел 1 «Философия Ponytail»), команда отказалась от добавления раздутых сторонних библиотек, решив все сложные прикладные задачи средствами стандартной библиотеки Python (Python Standard Library):

### 4.1. Генератор отчётов XLSX на чистом stdlib (`backend/app/reports_export.py`)
- **Проблема в типовых проектах:** Подключение тяжеловесных зависимостей (`openpyxl`, `xlsxwriter`, `pandas`), которые добавляют десятки мегабайт транзитивного кода и расширяют вектор атак.
- **Решение в rost_crm:**
  - Функция `generate_xlsx_report(report_data, report_type, user)` (строки 77–220) генерирует спецификацию Office Open XML (`.xlsx`) напрямую через стандартные модули:
    * `zipfile.ZipFile(buf, "w", compression=zipfile.ZIP_DEFLATED)` для создания архива.
    * `xml.sax.saxutils.escape()` для безопасной сериализации строк.
    * Прямая генерация XML-дескрипторов: `[Content_Types].xml`, `xl/workbook.xml`, `xl/styles.xml`, `xl/worksheets/sheet1.xml`.
  - **Брендирование Ростелекома:** Реализованы фирменная фиолетовая шапка (`#7700FF`), белый текст, чередующаяся подсветка строк (`#F4F5F8`), тонкие границы ячеек и автоматический расчёт ширины колонок.
  - **Защита от Formula Injection (CSV/XLSX Injection):** В функции `_xml_escape` (строки 16–24) реализована автоматическая нейтрализация: если ячейка начинается со спецсимволов `=`, `+`, `-`, `@`, значение экранируется префиксным апострофом `'`.
- **Экономия:** Исключены зависимости `openpyxl`, `et_xmlfile`, `xlsxwriter`. **0 добавленных библиотек.**

### 4.2. Векторный генератор отчётов PDF на чистом stdlib (`backend/app/reports_export.py`)
- **Проблема в типовых проектах:** Подключение системных библиотек рендеринга (`reportlab`, `weasyprint`, `pdfkit`, `PyMuPDF/fitz`), требующих C-компиляторов, cairo, pango и содержащих частые уязвимости переполнения буфера.
- **Решение в rost_crm:**
  - Функция `generate_pdf_report(report_data, report_type, user)` (строки 223–490) создаёт многостраничный векторный PDF 1.4 напрямую в памяти через `io.BytesIO()`.
  - Прямое формирование графических операторов языка PostScript/PDF:
    * Отрисовка плашек и заливок Ростелеком: `re`, `f`, цветовая модель RGB `rg`.
    * Текстовые блоки: `BT`, `Tf`, `Td`, `Tj`, `ET`.
    * Динамическая таблица кодировки ToUnicode CMap для корректного отображения кириллицы (шрифт Helvetica / Type1 с транслитерацией / UTF-16BE CID-маппингом).
    * Сквозная многостраничная верстка («Стр. X из Y»), фирменный колонтитул ПАО «Ростелеком» и гриф «КОНФИДЕНЦИАЛЬНО · ДСП».
- **Экономия:** Исключены `reportlab` и `weasyprint`. **0 добавленных библиотек.**

### 4.3. Двухфазный мастер импорта каталогов (`backend/app/importer.py`)
- **Проблема в типовых проектах:** Использование `pandas` / `openpyxl` для чтения загружаемых Excel/CSV файлов.
- **Решение в rost_crm:**
  - Функция `parse_xlsx_stdlib(data: bytes)` (строки 108–150): разбирает XLSX архив встроенным `zipfile` и парсит XML-структуру через `xml.etree.ElementTree` (`xl/sharedStrings.xml` и `xl/worksheets/sheet1.xml`).
  - Функция `parse_csv_stdlib(data: bytes)` (строки 152–168): читает CSV через стандартный `csv.reader` с автоматическим распознаванием разделителей (`;` или `,`) и детекцией кодировок (`utf-8-sig`, `utf-8`, `cp1251`, `latin1`).
- **Экономия:** Исключены `pandas`, `numpy`, `openpyxl`. **0 добавленных библиотек.**

### 4.4. Криптографическая целостность и файловая изоляция (`backend/app/files.py`)
- Валидация сигнатур (magic bytes) ровно 10 разрешённых форматов ТЗ без внешней уязвимой библиотеки `python-magic` / `libmagic`.
- Расчёт контрольных сумм вложений через встроенный `hashlib.sha256`.
- Изоляция путей и защита от Path Traversal (`../`) через стандартный `pathlib.PurePath`.

### 5.2. Регламент реагирования на новые уязвимости (SLA / Patch Management)
1. **Critical / High (CVSS >= 7.0):** Устранение в течение 24 часов путём выпуска patch-релиза базового образа или точечного обновления `pnpm-lock.yaml` / `.venv`.
2. **Medium / Low (CVSS < 7.0):** Анализ применимости контекста (Exploitability), исправление в рамках планового спринта (до 7 календарных дней).
3. **Неизменяемость реестра:** Любое добавление новой внешней зависимости требует согласования архитектора (Architecture Reviewer & Ponytail Guardian) с обязательным обоснованием невозможности решения задачи средствами `stdlib`.
