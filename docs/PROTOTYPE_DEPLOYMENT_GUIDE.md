# Руководство по развёртыванию действующего прототипа и сценарий экспертной проверки

Данный документ описывает процесс публичной публикации веб-прототипа CRM системы для выполнения требований п. 10.3 ТЗ («Ссылка на прототип для проверки выполненной работы — работающая CRM с предоставлением доступа на разработанный пользовательский web-интерфейс»).

---

## 1. Быстрый запуск на сервере (VPS / VDS / Выделенный хост)

### 1.1. Требования к серверу
- **ОС:** Linux x86_64 (Ubuntu 22.04 / 24.04 LTS, Astra Linux, Debian 12, CentOS/RedOS)
- **Аппаратные ресурсы:** от 2 vCPU, от 4 GB RAM, от 20 GB SSD
- **Порты:** 80, 443 (или порт 3000 при прямом доступе)
- **Установленное ПО:** Docker Engine 24.0+ и Docker Compose v2.20+

### 1.2. Пошаговые команды развёртывания
Выполните на сервере:

```bash
# 1. Клонирование репозитория
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ> /opt/rost_crm
cd /opt/rost_crm

# 2. Подготовка файла конфигурации
cp .env.example .env

# Если у вас есть публичный домен (например, crm.example.ru),
# укажите его в .env (для Keycloak OIDC redirects):
# KEYCLOAK_PUBLIC_URL=https://crm.example.ru/auth

# 3. Сборка и запуск всех 6 контейнеров стека
docker compose up --build -d --wait --wait-timeout 240

# 4. Наполнение базы данных реалистичными демонстрационными данными
docker compose exec api python -m app.seed --seed-demo

# 5. Проверка статуса сервисов
docker compose ps
```

## 2. Публичный доступ через Cloudflare Tunnel (Zero-Config HTTPS)

Если у сервера нет белого IP-адреса или доменного имени со статическим сертификатом, рекомендуется поднять защищённый туннель Cloudflare Tunnel (быстро, бесплатно, официальный HTTPS-сертификат Cloudflare):

```bash
# Установка cloudflared на сервере (Ubuntu/Debian)
curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared.deb

# Запуск мгновенного публичного HTTPS-туннеля к порту CRM (3000)
cloudflared tunnel --url http://localhost:3000
```
В терминале появится уникальная ссылка вида:
`https://<случайный-поддомен>.trycloudflare.com`

Эту ссылку можно напрямую вставить в поле сдачи решения на платформе!

## 4. Сценарий экспертной проверки функционала (Walkthrough Guide)

Рекомендуемый 5-минутный маршрут для эксперта жюри:

### Шаг 1. Проверка рабочего стола и Zero-Oracle изоляции
1. Авторизуйтесь как `manager-a` (`ManagerPass123!`).
2. На экране **«Обзор»** отображается персональная сводка: 8 взаимодействий, этапы воронки.
3. Перейдите в раздел **«Взаимодействия»** — отображаются только карточки Анны Смирновой.
4. Попробуйте ввести в URL ID чужого взаимодействия: система вернёт строгий экран `404 Not Found` (Zero-Oracle защита 152-ФЗ — факт существования чужих данных скрыт).

### Шаг 2. Прохождение воронки workflow и документооборот
1. Откройте карточку любого взаимодействия (например, «МГТУ им. Баумана — Сетевые технологии»).
2. В блоке **«Граф жизненного цикла»** нажмите кнопку перехода на следующий этап.
3. Попробуйте нажать «Отменить взаимодействие» — появится модальное окно с обязательным требованием указать причину (комментарий валидируется на сервере).
4. В блоке **«Документооборот и вложения»** перетащите файл (PDF или PNG до 25 МБ).
5. Файл моментально проходит потоковую антивирусную проверку ClamAV и отображается в списке с кнопкой безопасного предпросмотра и скачивания.

### Шаг 3. Функционал руководителя: переназначение куратора
1. Выйдите из системы (кнопка выхода в правом верхнем углу) и войдите как `supervisor-a`.
2. В реестре отображаются карточки всех менеджеров подразделения.
3. Перейдите в **«Справочники»** → нажмите **«Назначить ответственного»** у любой организации.
4. Выберите нового сотрудника и сохраните — обновление происходит реактивно без перезагрузки всей страницы (SPA).

### Шаг 4. Аналитический модуль и экспорт отчётов
1. Перейдите в раздел **«Отчёты»**.
2. Выберите тип отчёта: **«Срезовый (Snapshot)»** или **«Активности»**, укажите период.
3. Нажмите кнопку **«Скачать XLSX»** — сгенерируется чистый Excel-файл без сторонних библиотек.
4. Нажмите **«Скачать PDF»** и **«Скачать CSV»** — проверьте моментальную загрузку файлов.

### Шаг 5. Администратор: двухфазный импорт и мониторинг
1. Войдите под учётной записью `admin`.
2. Перейдите в **«Справочники»** → **«Импорт каталогов»**.
3. Загрузите файл `данные предоставленные организаторами/Вендоры.xlsx`.
4. Система выполнит предварительный разбор (**Фаза 1: Предпросмотр**) с валидацией строк до фиксации в БД.
5. Откройте пункт меню **«Интеграции»** — ознакомьтесь с журналом очередей входящих пакетов из LMS Zion и сайта.

### Шаг 6. Интерактивная документация Swagger и Health-пробы
- Swagger UI (OpenAPI 3.1): `http://<хост>:3000/docs`
- Проверка готовности СУБД, кэша и антивируса: `http://<хост>:3000/health/ready` (возвращает `{"status":"ready"}`)
