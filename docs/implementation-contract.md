# First working slice contract

Repository: outputs/rtk-crm. Product name: ИТ Школа · Партнёры. Russian UI. React+TypeScript/Vite, FastAPI+SQLAlchemy, PostgreSQL production target, explicit SQLite local development fallback. No claim of completed full ТЗ. Use outputs/04-base-workflow.json as actual workflow data, copied into backend/app/data/base-workflow.json. Existing report fixture defines temporal concepts but has a compact history, not executable base-workflow commands.

API prefix /api/v1. All responses JSON. Single origin proxy. Errors: {error:{code,message,request_id?,details?}}. Auth default OIDC, JWT RS256 verified issuer+audience+exp via JWKS. Development auth only if AUTH_MODE=demo AND APP_ENV=development; fail fast otherwise; explicit X-Demo-User header (no silent default). Demo data only via explicit seed command. Public GET /api/v1/config returns {auth_mode,oidc:{url,realm,client_id}|null,demo_users:[{id,name,role}]}; demo_users empty outside demo. Keycloak identity sub mapped to seeded User keycloak_subject; local UUID/short IDs opaque strings.

Demo user IDs: manager-a, manager-b, supervisor, administrator. Names Анна Смирнова, Михаил Волков, Елена Соколова, Администратор. Roles manager/supervisor/administrator. manager-a sees owned interactions; manager-b sees own; supervisor team north; administrator has management, no business data unless grant. All demo organizations and programs clearly marked synthetic in app/README, no real people data. Seed ids org-1,org-2,org-3; program-devops/program-qa; product-cloud/product-test; interactions ix-1...ix-6 with varied *actual* allowed workflow histories. Initialowner team stable on interaction team_id so scope not lost unexpectedly. User can list organizations only if scoped via owned/card/team or explicit org access grant. For initial creation allowed organization_ids per user in DB.

GET /me -> {id,name,role,permissions:[...],team_id,auth_mode}
GET /catalogs -> {organizations:[{id,name,type}],programs:[{id,name,direction_id,direction_name}],products:[{id,name,vendor}],owners:[{id,name}],directions:[{id,name}]} all scoped where needed. Minimal POST /organizations {name,type} optional supervisor/admin allowed.
GET /workflow -> full base-workflow.json object.
GET /interactions?q=&organization_id=&program_id=&product_id=&owner_id=&state=&page=1&page_size=50 -> {items:[Interaction],total,page,page_size}; validate page and filters. Search title/org; server scope before aggregation/pagination.
Interaction -> {id,title,organization_id,organization_name,program_id|null,program_name|null,product_id|null,product_name|null,direction_name|null,cycle_label,owner_id,owner_name,state,state_name,workflow_version,revision,created_at,updated_at,closed_at|null}
GET /interactions/{id} -> same Interaction plus {allowed_transitions:[{code,to,name,comment_required,condition_refs}],events:[Event],comments:[Comment]}
Event -> {id,type,effective_at,received_at,sequence,actor_name,from_state?,to_state?,owner_id?,comment?}; append-only. Creation includes original state+owner. Comment -> {id,body,author_name,created_at,visit_id?}
POST /interactions body {title,organization_id,program_id:null|id,product_id:null|id,cycle_label,owner_id}; Idempotency-Key required; 201 Interaction. Scope/owner assignment check. Default first state contact_search.
POST /interactions/{id}/transitions body {transition_code,expected_revision,comment?}; Idempotency-Key required ->200 Interaction. Atomic revision CAS, allowed graph, nonblank rework/cancel/cycle comment, programme/product required on entry materials_transfer and later phases. Replay same key+body idempotent; key+different payload409. No PUT/PATCH status shortcuts.
POST /interactions/{id}/comments body {body,expected_revision}; Idempotency-Key required ->201 Comment with interaction_revision in response; nonblank up to5000. Atomic revision and history.
POST /interactions/{id}/assignments body {owner_id,expected_revision,reason}; Idempotency-Key required ->200 Interaction. Supervisor ownteam only/admin explicit permission; manager forbidden. History and new revision.
GET /dashboard -> {total_interactions,total_organizations,active_interactions,completed_interactions,counts_by_state:[{code,name,count}],recent_events:[{interaction_id,title,event_type,actor_name,at}],unassigned_program_count}; scoped server counts.
POST /reports/snapshot body {as_of:ISO,knowledge_cutoff?:ISO,as_of_inclusive?:true,organization_ids?:[],program_ids?:[],product_ids?:[],owner_ids?:[]} -> {report_type:'snapshot',as_of,knowledge_cutoff,as_of_inclusive,generated_at,rows:[{interaction_id,title,organization_name,program_name,product_name,state,state_name,owner_id,owner_name}],totals:{interactions,organizations,counts_by_state:{code:number}}}. Current access + historical owner/state; effective+received filter and deterministic sequence. No extra access via old ownership. No asyncjob yet; small firstslice report explicitly limited.
POST /reports/snapshot/export samebody -> JSON file Content-Disposition attachment (initial resulting JSON only; no fake XLS/PDF yet).
GET /health/live and /health/ready. Swagger /docs usable API.
