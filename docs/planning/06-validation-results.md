## Что исправлено при сверке

- Выровнены коды ролей в спецификации и JSON: manager, supervisor, administrator.
- Уточнено различие снятия ответственного организации и смены владельца карточки.
- Инварианты заполненности поздних этапов применяются также при редактировании, импорте и миграции процесса.
- Состояние «Подписание» отделено от факта подписания; состояние «Передача» — от завершённой передачи.
- Для снимка на конец календарного дня введена явная исключающая граница; эталонные timestamp-снимки сохраняют включительную семантику.
- При одинаковом времени назначения и перехода учитывается sequence.
- Эталон отчётов помечен как компактная историческая проекция; он не выдаётся за последовательность допустимых команд базового процесса.
- Первоначальный ориентир трудоёмкости обновлён ссылкой на детализированный план.

## Воспроизведение

Из папки пакета выполнить на Python 3.10+:

```text
python checks/verify_workflow.py
python checks/verify_reports.py
python checks/verify_plan.py
```

Скрипты используют стандартную библиотеку и не изменяют файлы. Они включены в пакет. Ручная смысловая сверка документов дополняет автоматические проверки, но не означает согласование предложений заказчиком.

Все AC01–AC30 для будущей CRM имеют статус «не запускался». Реальные API, производительность, документы готового интерфейса, модель Archi и условия эксплуатации предстоит реализовать и проверить по плану.
