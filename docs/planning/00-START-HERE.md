# Пакет проектирования CRM ИТ Школы РТК

Версия 0.1, 17 сентября 2026 года.

Подготовлено для цели «победа на хакатоне и реальное внедрение». Это конкретная проектная основа для разработки: спецификация, задачи, критерии и проверочные данные. Приложение и реальные интеграции пока не реализованы. Проектные решения сверх исходного ТЗ помечены; согласование заказчиком не предполагается автоматически.

Спецификация задаёт базовые проектные правила. Backlog реализует их, приёмочные сценарии проверяют их. JSON workflow описывает граф переходов; общие инварианты данных и проверки доступа берутся из спецификации. Эталон отчётов является компактной исторической проекцией, а не набором допустимых команд этого графа: он используется отдельно от тестов переходов.

## Что зафиксировано

- Взаимодействие — отдельный цикл по организации, программе и продукту, с собственным ID. На ранних этапах программа/продукт могут отсутствовать.
- Ответственный организации и владелец карточки различаются; смена одного не переписывает незаметно другого.
- Опубликованные процессы версионируются; текущие карточки переносятся явно.
- Исторические значения и текущие права доступа проверяются отдельно.
- Отчёт различает время события, время получения данных и временные границы.
- XLS/XLSX/PDF, PNG и JSON включены в план; исключения исходного ТЗ не подменяются сокращённым набором форматов.
- Демонстрация, пилот и эксплуатационный выпуск имеют отдельные критерии готовности.

## Оценка и открытые зависимости

Детализация дала **121–209 человеко-дней** суммарного труда по 40 задачам. Это уточнение первоначального ориентира 80–140; теперь отдельно учтены сложные процессы, проверка доступа, реальные интеграции, испытания, восстановление, документация и ограниченный пилот. Календарный срок зависит от команды и внешних согласований. Оценка не является гарантированным потолком; неизвестные формальные процедуры ИБ и массовая очистка реальных данных не включены как известный объём.

Открыты реальные API-контракты, примеры каталогов, определения учебных метрик, окончательная матрица доступа, условия размещения и подтверждения ИБ. Для них есть Q01–Q09 в спецификации и X01–X06 в плане. Независимую разработку можно начинать на обозначенных проектных правилах и синтетических данных.

## Проверки, которые можно повторить

Требуется Python 3.10+; сторонние пакеты не нужны. Запускать из папки пакета:

```text
python checks/verify_workflow.py
python checks/verify_reports.py
python checks/verify_plan.py
```

Проверки читают файлы и ничего не изменяют. Они подтверждают структуру/связность примера workflow, расчёт 12 ожидаемых отчётов, арифметику задач, отсутствие циклов зависимостей и покрытие требований. Эти проверки не являются испытаниями будущей CRM. У всех 30 приёмочных сценариев приложения пока статус «не запускался».

## Первая инженерная итерация

Создать запускаемый контур: Keycloak → доступные организации → взаимодействие → переход по шаблону → комментарий → история → эталонный snapshot. Параллельно получить примеры от заказчика и уточнять зависимые правила. Следующие задачи расширяют этот контур до полного набора требований; готовность первого маршрута не означает готовность продукта к внедрению.
