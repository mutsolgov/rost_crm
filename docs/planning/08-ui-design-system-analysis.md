## 1. Контекст продукта: ИТ Школа Ростелекома и платформа rtkb

Платформа `rtkb.zion-lms.ru` представляет собой образовательную систему («ИТ Школа Ростелеком. Код будущего»), в которой учащиеся (школьники и студенты) проходят обучение по ключевым ИТ-направлениям:
- DevOps и системное администрирование
- Инженерия качества и тестирование ПО (QA)
- Веб-разработка и прикладное программирование (Python, C++)
- Анализ данных и искусственный интеллект

### Роль разрабатываемой CRM (`rost_crm`) в связке с LMS
- **LMS (`rtkb.zion-lms.ru`):** операционная платформа учебного процесса (учащиеся, преподаватели, вебинары, аттестационные листы, задания).
- **CRM (`rost_crm`):** система управления взаимодействием с образовательными организациями (вузами, колледжами, школами) для менеджеров (КАМ) и руководителей ИТ Школы Ростелекома.
- CRM автоматизирует 14 этапов жизненного цикла партнерства: от первого поиска контактов в вузе и подписания договоров/лицензий до внедрения программ, повышения квалификации преподавателей и агрегации учебных показателей востребованности (заявки, активные студенты, параллельные потоки).

## 2. Анализ дизайн-системы Ростелекома Gen2 (Atomaro UI)

Дизайн-система Ростелекома второго поколения (**Atomaro**) базируется на строгих гайдлайнах доступности, модульной компонентной структуре и системе дизайн-токенов на основе CSS-переменных.

### 2.1. Цветовая модель темы «Rostelecom Light Theme»

| Токен / Роль | Значение HEX | Назначение в интерфейсе |
|---|---|---|
| **Primary Brand (Фиолетовый)** | `#7700FF` / `#6C00E0` | Основной цвет бренда: активные элементы, первичные кнопки, выделение навигации, бейджи ключевых сущностей. |
| **Accent / Action (Оранжевый)** | `#FF4F12` / `#FF6A13` | Фирменный акцент Ростелекома: кнопки целевого действия (CTA), маркеры шагов, индикаторы конверсии, яркие бейджи. |
| **Background (Основной фон)** | `#F4F5F8` | Нейтральный светлый фон рабочих страниц (high comfort, снижение усталости глаз). |
| **Surface (Поверхность)** | `#FFFFFF` | Фон карточек, модальных окон, таблиц и выпадающих панелей. |
| **Border / Divider** | `#E2E5EB` / `#E8EAF0` | Тонкие контрастные границы карточек, разделители таблиц и полей ввода. |
| **Text Primary** | `#101828` | Заголовки, основной текст данных, контраст > 10:1 (соответствие требованиям доступности). |
| **Text Secondary** | `#475467` | Подписи полей, вторичные метаданные, поясняющий текст. |
| **Text Muted / Caption** | `#667085` | Плейсхолдеры, даты, вспомогательные счетчики. |
| **Success State** | `#039855` (фон `#ECFDF3`) | Этап «Завершено» (`completed`), успешный импорт, валидные проверки. |
| **Warning State** | `#DC6803` (фон `#FEF0C7`) | Внимание, доработка документов (`document_revision`), пропуск срока. |
| **Danger / Cancelled State** | `#D92D20` (фон `#FEF3F2`) | Этап «Отменено» (`cancelled`), ошибки валидации, деструктивные действия. |
| **Info / Progress State** | `#0088FF` (фон `#EFF8FF`) | Активные стадии внедрения, обучение преподавателей, занятия. |

### 2.2. Типографика и сетка
- **Базовый шрифт:** `Circe`, `Inter`, `system-ui` (четкие гротески с развитой поддержкой кириллических глифов).
- **Размеры заголовков:** H1 (28–32px, bold), H2 (20–24px, semibold), H3 (16–18px, semibold).
- **Основной текст:** 14px (Body regular, line-height 1.5), 13px (Body small / Table data), 11–12px (Captions / Badges).
- **Скругления (Border Radius):**
  - Кнопки, инпуты, теги: `8px`
  - Карточки, блоки дашборда: `12px` – `16px`
  - Модальные окна и дропдауны: `16px`
- **Тени (Elevation):**
  - Card: `0 1px 3px rgba(16, 24, 40, 0.05), 0 1px 2px rgba(16, 24, 40, 0.03)`
  - Hover: `0 4px 12px rgba(16, 24, 40, 0.08)`
  - Modal / Overlay: `0 20px 48px rgba(16, 24, 40, 0.16)`

## 3. Компонентная архитектура в соответствии с React Storybook Gen2

Поскольку пакет `@atomaro` является закрытой внутренней библиотекой Ростелекома и не распространяется публично в npmjs, интерфейс CRM реализует точную спецификацию Storybook через собственный слой дизайн-токенов и компонентов:

```
frontend/src/
├── styles/
│   ├── tokens.css               <-- CSS-переменные Rostelecom Light Theme (--rtk-*)
│   ├── base.css                 <-- Сброс, шрифты, типографика
│   └── components.css           <-- Стили компонентов по спецификации Storybook
├── components/
│   ├── ui/
│   │   ├── Button.tsx           <-- Primary (фиолетовый), Secondary, Ghost, Danger
│   │   ├── Badge.tsx            <-- Статусы, этапы, цветовые индикаторы
│   │   ├── Input.tsx            <-- Поля ввода с состояниями ошибки/успеха
│   │   ├── Select.tsx           <-- Выпадающие списки
│   │   ├── Stepper.tsx          <-- Визуализатор 14 этапов процесса взаимодействия
│   │   ├── Table.tsx            <-- Таблицы с сортировкой, пагинацией и селектором колонок
│   │   ├── Modal.tsx            <-- Диалоговые окна подтверждения и форм
│   │   ├── Tabs.tsx             <-- Вкладки рабочих разделов
│   │   └── Drawer.tsx           <-- Боковая шторка детального просмотра
```

## 4. Требования к UI экранов CRM по продуктовому эталону rtkb

### 4.1. Главный экран (Дашборд и Обзор)
- **Метрики верхнего уровня:**
  - Карточки показателей (Всего взаимодействий, Активные партнерства, Вузы-партнеры, Обучающиеся студенты).
  - Сводка востребованности: 3 ключевых счетчика из ТЗ (заявки, обучающиеся, потоки).
- **Интерактивная воронка этапов:**
  - Наглядное отображение распределения карточек по 14 этапам жизненного цикла.
  - Клик по этапу фильтрует реестр взаимодействий.
- **Блок последних событий команды:**
  - Хронологическая лента изменений с указанием автора, вуза и нового статуса.

### 4.2. Реестр взаимодействий
- **Многоуровневая фильтрация:**
  - Поиск по названию вуза / программы.
  - Селекты: Организация, ИТ-программа, ИТ-продукт, Этап workflow, Ответственный менеджер.
  - Сохранение фильтров в URL / состоянии без перезагрузки страницы (SPA).
- **Настройка колонок таблицы:**
  - Возможность скрывать / отображать колонки (вуз, договор, лицензия, ответственные, статус).
- **Адаптивность:**
  - На десктопе — полноразмерная таблица данных.
  - На планшетах и мобильных — карточный вид с быстрым доступом к действию.

### 4.3. Карточка взаимодействия и Workflow Stepper
- **Визуализация 14 этапов:**
  - Верхний прогресс-бар (Stepper) с подсветкой пройденных, текущего и предстоящих шагов.
- **Управление переходом:**
  - Отображение ВСЕХ разрешенных альтернативных переходов из текущего статуса (продолжить, вернуть на доработку, отменить).
  - Модальное окно подтверждения с обязательным комментарием для нелинейных переходов.
- **Редактирование параметров карточки:**
  - Возможность дозаполнить ИТ-программу, ИТ-продукт, договорные реквизиты.
- **Вкладки карточки:**
  1. *Основное и Договоры:* поля ТЗ (номер договора, лицензия, срок, статус передачи, ответственные лица вуза).
  2. *Вложения:* загрузка и скачивание документов 10 форматов.
  3. *История и Аудит:* хронологический таймлайн событий и комментариев.

### 4.4. Раздел «Отчёты и Экспорт»
- **Параметры формирования:**
  - Выбор режима: «Снимок на дату» (`snapshot`) или «Активность за период» (`activity`).
  - Фильтры по организациям, программам, продуктам, ответственным.
  - Выбор выгружаемых колонок чекбоксами.
- **Кнопки экспорта:**
  - «Скачать Excel (.xlsx)»
  - «Скачать PDF (.pdf)»
  - «Скачать JSON (.json)»

### 4.5. Раздел «Импорт каталогов»
- Загрузка файлов `.xlsx` / `.xls`.
- Предпросмотр распознанных строк и маппинг колонок на 10 полей ТЗ.
- Валидация ошибок и отчет о результатах импорта.

### 4.6. Раздел «Интеграции (LMS и Сайт)»
- Карточки внешних источников (`rtkb.zion-lms.ru` и веб-сайт на Laravel).
- Статус последнего обмена данными, количество полученных заявок и метрик.
- Кнопка ручной синхронизации и журнал входящих пакетов.

## 5. План полной реализации системы (без ограничений по времени)

Учитывая указание реализовать систему **в полном объеме всех требований ТЗ**, сформирован сквозной план работ:

1. **Фаза 1: Расширение схемы данных и ядра API**
   - Добавление таблиц `contracts`, `licenses`, `organization_contacts`, `attachments`.
   - Добавление методов `PATCH /api/v1/interactions/{id}`, `POST /api/v1/interactions/{id}/attachments`, `GET /attachments/{id}/download`.
   - Задачи бэклога: B11, B14, B18.

2. **Фаза 2: Рефакторинг UI на дизайн-систему Ростелекома Gen2**
   - Внедрение токенов `Rostelecom Light Theme` (`tokens.css`).
   - Реализация Stepper для 14 этапов, отображение всех переходов, формы редактирования карточки.
   - Задачи бэклога: B15, B20, B28.

3. **Фаза 3: Полнофункциональные отчёты (Excel XLSX, PDF, JSON)**
   - Генерация отчетов через `openpyxl` и `reportlab` с выбором колонок.
   - Поддержка режима `activity` (переходы за период).
   - Задачи бэклога: B22, B24.

4. **Фаза 4: Импорт каталогов из Excel XLS/XLSX**
   - Парсинг файлов Excel, мастер маппинга полей, валидация и загрузка в БД.
   - Задачи бэклога: B12, B13.

5. **Фаза 5: Аналитические диаграммы и визуализация**
   - Графики воронки и востребованности программ, экспорт в PNG и PDF.
   - Задачи бэклога: B25.

6. **Фаза 6: Интеграционный контур LMS (`rtkb`) и сайта Laravel**
   - Модели синхронизации, забор данных по утвержденной JSON-схеме, добавление в workflow.
   - Задачи бэклога: B26, B27, B28, B29.

7. **Фаза 7: Встроенная документация, Archi и поставка**
   - Встроенные иллюстрированные руководства со скриншотами.
   - Модель Archi (`.archimate`), инструкция развертывания под Linux.
   - Задачи бэклога: B34, B35, B36, B39.
