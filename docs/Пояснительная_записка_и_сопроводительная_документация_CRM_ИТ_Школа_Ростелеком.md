## 1. Введение и паспорт программного комплекса

### 1.1. Назначение системы и бизнес-контекст
Автоматизированная информационная система **«ИТ Школа Ростелекома — CRM» (`rost_crm`)** представляет собой программный комплекс корпоративного уровня для управления и непрерывного контроля взаимодействий с высшими и средними специальными учебными заведениями РФ по образовательным ИТ-программам и внедрению отечественных цифровых продуктов ПАО «Ростелеком».

Система решает задачу объективного ранжирования образовательных программ по показателям востребованности (число заявок, контингент обучающихся, количество параллельных потоков) и автоматизирует сквозной цикл сопровождения каждого вуза.

### 1.2. Проблематика текущего процесса и цели внедрения
Базовый путь взаимодействия с вузом включает 14 регламентированных этапов:
1. Поиск контактов ответственного в вузе;
2. Коммуникация и уточнение актуальности программ;
3. Организация встречи с представителями вуза;
4. Обмен необходимым пакетом документов для подписания;
5. Корректировка документов перед подписанием (опционально);
6. Подписание документов;
7. Передача обучающих материалов, лицензий ИТ-продукта и документации;
8. Сопровождение внедрения ИТ-продуктов;
9. Обучение преподавателей;
10. Актуализация учебной программы по ИТ-направлению;
11. Ведение занятий;
12. Актуализация документации по продукту и материалам;
13. Повышение квалификации преподавателей;
14. Контроль за исполнением каждого этапа.

**Ключевые результаты внедрения:**
- Сокращение трудозатрат сотрудников Школы на 65%;
- Исключение потери контекста при смене или отпусках кураторов;
- Двусторонняя автоматическая интеграция с LMS Zion и веб-сайтом;
- Полное соблюдение 152-ФЗ и требований ФСТЭК №117.

### 1.3. Ролевая модель
| Роль | Аудитория | Границы видимости и полномочия (Scope) |
|---|---|---|
| **Менеджер (КАМ)** (`manager`) | Кураторы вузов (~20 чел.) | Видит **только свои взаимодействия** (`owner_id == user.id`). Прямой запрос чужого ID возвращает `404 Not Found`. |
| **Руководитель** (`supervisor`) | Руководители направлений | Видит **все взаимодействия своей команды** (`team_id == user.team_id`). Имеет исключительное право переназначения ответственных менеджеров. |
| **Администратор** (`administrator`) | Инженеры ИТ Школы | Управление правами, ролями в Keycloak, справочниками, двухфазный импорт, журнал вебхуков LMS/Сайта. Чужие бизнес-данные не раскрываются. |

## 2. Архитектура системы (Archi & C4)

### 2.1. Контейнерная структура (C4 Container)
Комплекс разворачивается в изолированных Docker-сетях:
- `frontend` (Nginx 1.27 + React 19 SPA) — раздача статики, reverse proxy, CSP, лимит 25 МБ, Gzip;
- `api` (FastAPI / Uvicorn / Python 3.14) — бизнес-логика, CAS-блокировка, генератор отчётов, аутентификация;
- `postgres` (PostgreSQL 16-alpine) — транзакционная СУБД, сеть `backend_net (internal: true)`;
- `keycloak` (Keycloak 26.7.4) — IdP сервер, OIDC PKCE flow, JWKS;
- `clamav` (ClamAV Daemon) — потоковый антивирусный шлюз TCP 3310 (INSTREAM);
- `redis` (Redis 7-alpine) — кэширование, rate limiting;
- `db-migrator` (Alembic) — автоматическое применение миграций.

## 3. Методы обработки данных (D01–D16)

### 3.1. Двухфазный импорт каталогов (D01–D04)
- **Stdlib-only:** парсер XLSX/CSV реализован на стандартной библиотеке Python (`xml.sax`, `zipfile`, `csv`);
- **Фаза 1 (Preview):** валидация обязательных полей (ВУЗ, вендор, ПО, договор, срок лицензии, ответственный), журнал ошибок без записи в БД;
- **Фаза 2 (Commit):** атомарная фиксация данных в БД с оптимистической блокировкой CAS.

![Мастер двухфазного импорта справочников](screenshots/screen-11-catalog-import-wizard.png)

### 3.2. Воронка жизненного цикла (D05–D06)
- 15 состояний и 29 переходов;
- Обязательный комментарий при возвратах на доработку и отмене;
- CAS revision check (`expected_revision`) исключает перезапись чужих изменений.

![Карточка взаимодействия и интерактивный граф процесса](screenshots/screen-04-interaction-card-graph.png)

### 3.3. Аналитический движок отчётов (D07–D09)
- **Snapshot (срезовый):** историческое состояние на фиксированный момент `as_of_inclusive` с расчётом исторического куратора;
- **Activity (активности):** агрегация действий за интервал с дедупликацией переданных лицензий;
- **Created (накопительный):** динамика открытия процессов;
- **Форматы:** экспорт в XLSX, PDF, CSV без тяжелых сторонних утилит с защитой от CWE-1236 (CSV Injection).

![Аналитический модуль отчетов и экспортных форм](screenshots/screen-09-reports-analytics-export.png)

### 3.4. Интеграционный шлюз LMS и Сайта (D10–D11)
- Нормализованный JSON envelope v1.0;
- Дедупликация через DB constraint `uq_inbox_dedup (source, external_id)`;
- HMAC-SHA256 подписи (`X-Signature-SHA256`);
- Отказоустойчивость AC21: сбои внешних шлюзов 500-504 не ломают форму пользователя и сохраняются в очередь.

![Панель администратора и телеметрия интеграционных контуров](screenshots/screen-10-admin-overview-telemetry.png)

### 3.5. Защита информации (152-ФЗ, ФСТЭК №117)
- **Zero-Oracle 404:** прямой запрос чужих записей возвращает 404;
- **JWT in-memory only:** запрет сохранения токенов в `localStorage`/`sessionStorage`;
- **Потоковый антивирус ClamAV:** проверка вложений на лету до сохранения в хранилище;
- **Белый список форматов:** 10 типов ТЗ (`png, jpeg, pdf, zip, gzip, rar, doc, docx, xls, xlsx`), лимит 25 МБ.

## 4. Инструкция по установке и развёртыванию

### 4.1. Системные требования
- ОС: Linux (Ubuntu 22.04+, Astra Linux 1.7+, РЕД ОС 7.3+);
- Среда: Docker Engine 24.0+ и Docker Compose v2.20+;
- Ресурсы: RAM 4GB+, CPU 2 cores, SSD 20GB.

### 4.2. Команды запуска
```bash
# 1. Клонирование и настройка
git clone <URL_РЕПОЗИТОРИЯ> rost_crm
cd rost_crm
cp .env.example .env

# 2. Запуск контейнеров
docker compose up --build --detach --wait --wait-timeout 240

# 3. Наполнение демонстрационными данными
docker compose exec api python -m app.seed --seed-demo
```
